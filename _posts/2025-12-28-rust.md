# 정리
* rust 공식 문저는 여기.
    * https://rust-lang.org/

* 조금더 쉽고, 잘 배우기 위해서 아래 문서를 보면서 배우는것도 좋다.
    * https://doc.rust-lang.org/book/
    * https://doc.rust-kr.org/ (한글화)

* 위의 문서를 통해 배운 내용을 실습을 통해 더 견고히 해보는것도 추천한다.
    * https://rustlings.rust-lang.org/

* 실습이 러스트 문서 어느부분과 매칭이 되는지 알아보려면 아래를 통해 확인해 보자.
    * https://github.com/rust-lang/rustlings/tree/main/exercises#exercise-to-book-chapter-mapping

* 각종 rust 의 도구들은 아래와 같은 것들이 있다. 
    * Rustup : 툴체인 / 버전 관리자
    * Rustc : 러스트 컴파일러
    * Rustfmt : 코드 포매터
    * Clippy : 린터
        * https://rust-lang.github.io/rust-clippy/master/index.html  에서 사용가능한 린팅 규칙목록을 볼수있다. 
        * clippy::all :  기본으로 켜져 있는 모든 린트
        * clippy::correctness: 완전히 잘못됐거나 쓸모없는 코드
    * Cargo : 패키지 관리자
    * crates.io : 패키지 저장소

* 대시 2개 (--) 를 추가하면 인자값을 전달할수 있다
    * cargo 명령어에서는 -- 는 cargo 옵션과 실행 파일(프로그램) 옵션을 구분하는 역할을 한다.
        * -- 이전에 오는 옵션은 cargo 가 해석하고,
        * -- 이후에 오는 값들은 컴파일된 바이너리에 그대로 전달되는 인자값이다.
        * -- 가 있더라도 무조건 인자값으로 전달되는것은 아니고 --release 같은것은 cargo 가 직접 해석한다.
            * ex. cargo run --release -- hello world
                * hello 와 world 가 인자값으로 전달된다.
    * cargo 에는 dev, release 2개의 기본 프로필이 있다 기본적으로 cargo build 를 할땐 dev 프로필을 이용한다.
    * release 용으로 빌드하기 위해선 --release 플래그를 추가해서 사용해야 한다.

* rust 에서 문자열 다루면서 소유권을 알아 보자.
    * String 과 &str 의 주요 차이는 문자열 크기의 조정 여부
    * String 은 벡터로 구현되어있는 바이트 모음이다 (https://doc.rust-lang.org/src/alloc/string.rs.html#360-362)
    * &str(리터럴)은 수정할수 없는 u8값의 표현이다.
    * 즉 단순히 문자열을 읽기만 한다면 &str로, 문자열을 소유하고 수정하려면 String 타입을 사용해야한다.

```
pub struct String {
    vec: Vec<u8>,
}
```


* 아래 코드로 하면 hello world 출력되지만

```
// &str 타입의 새로운 변수를 만들어 y=x로 동일한 메모리 주소의 새 포인터를 만든다.
fn main() {
    let x = "hello world";
    let y = x;
    println!("{}", x);
}
```


* 아래 코드에선 컴파일 오류가 발생할것이다. (borrow of moved value: x 라는)
    * 참고로 to_sting 를 사용하면 &str을 String 로 변환할 수 있다.

```
// String 를 생성하고 단일 소유권 원칙이 적용되어 y=x 로 재할당 하게 되면 소유권이 x 에서 y로 옮겨진다.
// 내부적으로 uninit 로 표시된다. (https://doc.rust-lang.org/nomicon/drop-flags.html) 
let x = String::from("hello world");
let y = x;
println!("{}", x);
```

* Option 은 null 값이 반환되지 않도록 명확히 하는것이다. Option 열거 타입을 사용하면 컴파일러가 Some 또는 None를 처리한다.
* Result 는 Option 과 거의 비슷하면 성공 또는 에러 2가지중 하나를 나타낸다. 성공의 경우 Ok(value), 에러의 경우 Err(error)로 캡슐화 한다.

```
pub enum Result<T, E> {
    Ok(T),
    Err(E),
}
```

* 러스트는 비동기 백그라운드 작업을 처리할 수 있는 런타임을 기본적으로 제공하지 않기에, 아래 코드와 같이 [tokio::main] 이라는 구문을 넣어 해당 런타임을 사용하겠다라고 명시해줘야 한다.
    * 런타임은  스레드를 생성하고 퓨처를 폴링하고 완료까지 담당한다. 

```
#[tokio::main] <---- 요거.
async fn main() {
    ...
}
```

* 각종 유용한 라이브러리들

* Serde
    * 직렬화, 역직렬화 메서드를 프레임워크로 묶어놨다. 구조체를 json , toml, bson 같은 형식으로 변환, 역변환 할수있다.

```
#[derive(Debug, Serialize)]
struct Struct1 {
    name: String,
    id 
}
```

* Rc, Arc 타입
    * 기본 데이터 구조 T를 힙에 배치하고 스택에 포인터를 생선한다. 동일한 데이터를 참조하는 해당 포인터의 복사본을 만들수있다.  Rc는 단일 스레드 시스템에서 작동하고, Arc는 다중 스레드를 위한것이다. 
    * Arc 타입은 원자적 참조 카운터이다. 안에 감싼 데이터를 힙으로 옮기고, 스택에 포인터를 생성하는 컨테이너로 볼 수 있다. Arc 를 복제할 때는 힙에 있는 동일한 데이터 구조를 가리키는 포인터를 복제하고 내부적으로 Arc 카운트를 증가. 
    * 내부 카운트가 0에 도달하면 Arc 값을 삭제한다. 

```
// Arc의 카운트를 1 증가시킨다.
let x = Arc::new(String::from("helloeowrold"));
let y = Arc::clone(&x);
```

* rust 의 문서화
    * 러스트는 문서 주석과 공개되지 않는 주석을 다음과 같이 구분한다. cargo doc으로 프로젝트 문서를 자동으로 게시할 수 있다.

```
/// : 한줄짜리 문서 주석
/** ...*/ : 블록 문서 주석
// : 한줄 주석(공개되지 않음)
/* ... */ : 블록 주석(공개되지 않음.)
```

* 도커로 배포해 보자.
    * 로컬환경에서 빌드한것을 다른환경에서 실행시키려면 크로스컴파일이 필요한데, 러스트는 https://doc.rust-lang.org/rustc/platform-support.html#tier-1-with-host-tools 처럼 다양한 환경에 대해 컴파일을 지원한다.  
    * rustup target list 명령으로 사용할 수 있는 target 목록을 얻을 수 있다.

```
% rustup target list
aarch64-apple-darwin (installed)
aarch64-apple-ios
aarch64-apple-ios-macabi
aarch64-apple-ios-sim
x86_64-apple-darwin
.
.
.
```
    * 특정 환경에 대한 코드베이스를 구축하려면 먼저 Rustup으로 툴체인에 추가하려는 대상을 추가해야한다. 
    * 가령 M1 macos 머신에서 intel용 mac 바이너리를 빌드하려면 아래처럼 target을 먼저 추가한 다음 빌드 단계에서 지정해야한다.

```
% rustup target install x86_64-apple-darwin
% cargo build --release --target x86_64-apple-darwin
```

* 도커 이미지를 생성해보자.
    * Dockerfile 샘플.

```
# ----------------------------------------
# 1단계: Rust 빌드용 이미지
# ----------------------------------------
FROM rust:latest AS builder

# musl 타겟 추가 (정적 바이너리용)
RUN rustup target add x86_64-unknown-linux-musl

# musl 관련 도구 설치
RUN apt-get update && apt-get install -y \
    musl-tools \
    musl-dev \
    build-essential \
    && rm -rf /var/lib/apt/lists/*

# 작업 디렉토리 설정
WORKDIR /app

# 소스 코드 복사
COPY . .

# ----------------------------------------
# M1(Mac ARM) 환경에서 x86_64 musl 빌드를 위한 설정
# ----------------------------------------
# musl 타겟용 링커를 명시적으로 지정
ENV RUSTFLAGS="-C linker=x86_64-linux-gnu-gcc"

# 기본 C 컴파일러
ENV CC=gcc

# musl 타겟 전용 컴파일러 지정
ENV CC_x86_64_unknown_linux_musl=x86_64-linux-gnu-gcc

# ----------------------------------------
# musl 타겟으로 release 빌드
# ----------------------------------------
RUN cargo build --release --target x86_64-unknown-linux-musl

# ----------------------------------------
# 2단계: 최종 실행용 이미지 (최소 크기)
# ----------------------------------------
FROM scratch

# 실행 디렉토리
WORKDIR /app

# 빌드된 바이너리 복사
# (※ rust-sample 은 Cargo.toml의 [[bin]] 또는 패키지 이름)
COPY --from=builder \
    /app/target/x86_64-unknown-linux-musl/release/rust-sample \
    /app/rust-sample

# 환경 변수 파일 복사 (필요한 경우)
COPY --from=builder /app/.env /app/.env

# 실행 명령
CMD ["/app/rust-sample"]

```
